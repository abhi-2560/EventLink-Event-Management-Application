# Questions to Ask the Client — Direct Script

*Phrased to ask verbatim. Follow-ups in italics are there to catch edge cases if the first answer is vague.*

---

## 1. Problem, Goals & Users

1. "What's the core problem you're trying to solve with this project?"
2. "What made this a priority right now — is there a specific event, deadline, or trigger behind it?"
3. "What happens today if we don't build this — what's it currently costing you, in time or money or errors?"
4. "What are the two or three business outcomes you most want from this? For example, saving time, increasing revenue, or improving the experience for attendees?"
5. "Who will actually use this day-to-day? Can you name the roles — for example, admins, organizers, registrants?"
   *"Will one person ever need more than one of those roles at once — for example, someone who both organizes their own events and registers for others'?"*
6. "Besides the people using it directly, are there other teams or systems that need to plug into this — finance, marketing, support?"

## 2. Scope

7. "In your own words, what does this system need to do at a minimum for you to call it launched?"
8. "Is there anything you're imagining for this project that you'd be okay *not* having in the first version?"
9. "Are we replacing an existing system, extending one, or building something completely new?"
10. "Is there a hard deadline this needs to hit — a launch date, an event date, a budget cycle?"
11. "Is the budget fixed, or is there flexibility if we find the scope needs to grow?"
12. "If the timeline and the full feature list end up in conflict, which one bends — do we cut scope, or push the date?"

## 3. What Success Looks Like

13. "Six months after launch, how will you know this was worth building?"
14. "Is there a number you're targeting — like handling a certain number of registrations, or cutting processing time by some percentage?"
15. "Is there anything that, even if the software technically works, would make you consider this a failure?"

---

## 4. Current Process

16. "Walk me through exactly how this gets done today, step by step, from start to finish."
17. "At each of those steps, who owns it — is it one person, a team, or does it bounce between people?"
18. "What tools or software are you using for this today, if any — spreadsheets, email, another platform?"
19. "What's the most frustrating or time-consuming part of the current process, in your opinion?"
20. "Where do things usually go wrong or get delayed — is there a specific step that causes the most problems?"
21. "Are there any manual workarounds people have created to deal with gaps in the current process?"
22. "Roughly what volume are we dealing with — how many events, and how many registrants per event, at a normal time versus your busiest time?"

---

## 5. Functional Requirements

23. "Walk me through what a registrant should experience from the moment they find an event to the moment they're confirmed — what should happen at each step?"
   *"What should happen if the event is full when they try to register — waitlist, blocked entirely, something else?"*
24. "What can an organizer do that a registrant can't, and what can an admin do that an organizer can't?"
   *"Is there anything an organizer should need admin approval for — like publishing an event, or is it fully self-serve?"*
25. "Do events have a maximum number of attendees? Is that a hard cap or a soft target?"
   *"If an event is full, do you want a waitlist? What happens when a spot opens up — automatic promotion, or does someone need to approve it?"*
26. "What should happen if a registrant wants to cancel — do they get a refund, does their spot go to someone on a waitlist, is there a cutoff date after which they can't cancel?"
27. "What should happen if an organizer cancels an entire event — should all registrants be notified automatically, and is there a refund process?"
28. "Is money changing hands anywhere in this — paid tickets, deposits, refunds — or is this registration-only with no payments?"
29. "Do you need automatic emails or texts — for example registration confirmation, reminders before the event, cancellation notices? At what point should each one trigger?"
30. "What reports or data exports do you need — attendee lists, revenue summaries, attendance numbers? Who needs to pull those, and how often?"
31. "Does this need to connect to any other tools you already use — calendar apps, payment processors, a CRM, email marketing platform?"
32. "Do you need a record of who changed what and when — for example if an organizer edits an event after people have registered?"

## 6. Non-Functional Requirements

33. "Is there any data privacy or compliance requirement I should know about — GDPR, data staying within a certain country, industry-specific rules?"
34. "Who should be able to see personal information like emails, phone numbers, or payment details — is that restricted to certain roles?"
35. "Do you expect any traffic spikes — for example, everyone registering the moment a popular event opens? Roughly how many people at once?"
36. "What response time or load time would feel acceptable to you versus frustrating?"
37. "Do you expect this to grow to support multiple organizations or clients using the same system, or is it just for your organization?"
38. "How much would it hurt you if the system went down for an hour — is there a time of day or a day of the week where downtime would be especially bad, like during an active event?"
39. "How important is it that we can restore data quickly if something goes wrong — do you have a sense of how much data loss, if any, would be acceptable?"
40. "Do you have any requirements around hosting, infrastructure, or a specific tech stack I need to work within?"

## 7. Stakeholders

41. "Who has final sign-off on requirements — is that you, or someone else I should loop in?"
42. "Besides yourself, who else will be a regular user of this system?"
43. "Is there someone technical on your side — IT, security, compliance — who needs to review this before launch?"
44. "Who should I go to when I have a question during development — is that always you, or does it depend on the topic?"
45. "Are there other vendors, contractors, or internal teams I'll need to coordinate with?"

## 8. Prioritization

46. "Of everything we've talked about, what are the absolute must-haves — the things that mean this can't launch without them?"
47. "What would you call 'important but not a dealbreaker' — things where a manual workaround could hold you over for version one?"
48. "What's a 'nice to have' that you'd be happy with in a later version?"
49. "Is there anything we discussed that you'd like to explicitly rule out for now, so we don't circle back to it later?"

---

## 9. Practical & Contractual

50. "How often would you like updates from me — a weekly call, async messages, demos at certain milestones?"
51. "Who needs to approve designs or wireframes before I start building, and how many rounds of revisions should I expect?"
52. "Is there existing data — past events, existing registrants — that needs to be brought into the new system?"
53. "Do you have brand guidelines, a design system, or existing UI I should match, or is the visual design fully up to me?"
54. "After launch, who's responsible for maintaining this — you, an internal team, or is that part of our ongoing agreement?"
55. "Do you need separate staging or test environments, or just production?"
56. "Will you or your team want to test the system yourselves before it goes live, and how much time should I build in for that?"
57. "Who owns the code and the data once this project is delivered?"

---

### How to use this in the room
Don't fire these one after another like a checklist — let the conversation flow and check items off as they come up naturally. Use the italicized follow-ups only when an answer feels vague (e.g. "we'll figure that out later" on capacity or roles is a signal to press gently, since that ambiguity will cost you time mid-build).
